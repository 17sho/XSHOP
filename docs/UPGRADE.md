## 正式版本入口

当前正式发布：[1.1.9 — 游客订单查询与验证码参数修复](https://github.com/17sho/XSHOP/releases/tag/xshop-production-v1.1.9)。后续版本以 [GitHub Releases](https://github.com/17sho/XSHOP/releases/latest) 为准。

1.1.9 的 tag 为 `xshop-production-v1.1.9`，发布资产包括：

- `xshop-production-v1.1.9-linux-amd64.tar.gz`：Linux amd64 程序升级包。
- `xshop-production-v1.1.9-source.tar.gz`：对应源码包。
- `manifest.json`、`manifest.sig`、`public-key.txt`：签名清单、签名与公钥资料。
- `LICENSE`：许可证。

默认分支是独立保留的源码快照，不能由 README 的版本链接推断它等于 1.1.9。复现正式版请使用对应发布的源码包。公钥资料不等于授权更换已部署 helper 的可信签名 authority。

## 已接入正式升级通道的站点

以下步骤以 1.1.9 的正式发布说明为依据，适用于已配置生产签名升级通道的 XSHOP 站点，不是新站 bootstrap 脚本。

1. **先备份**：保留当前程序、配置、数据库的一致性备份与上传文件；核对目标版本和兼容性。不要仅备份程序。
2. **检查更新**：由超级管理员进入后台升级入口，检查正式版本并核对版本说明。
3. **下载并确认应用**：按后台流程操作；现有升级器校验签名清单、包的完整性及适用策略，不接受将任意上游包作为 XSHOP 更新。
4. **按提示重启**：确认升级完成后核对实际运行版本。若已打开的旧页面没有刷新，手动刷新一次以获取新后台资源。
5. **验收业务与资源**：检查站点品牌、上传图片、保留配置和关键业务入口。真实支付、邮件与验证码提供商需要单独验收，不能由程序健康检查代替。

如果后台没有升级入口，或尚未完成可信 helper / policy 接线，不要假设下载压缩包就能自动安装。首次安装与升级器 bootstrap 需要独立部署审核；这里不提供自动修改服务器权限或签名策略的命令。

## 保留数据，不复制测试环境

正式 1.1.9 仅包含应用代码及内嵌前后台资源，不包含测试站数据库、配置、Redis、worker/service、会员规则、商品库存或业务记录。测试站设置的验证码长度不会复制到正式站；正式站保留自身设置，需要时由管理员调整。

升级应保留正式站的用户、订单、余额、卡密、上传文件、凭据及运营设置。包不携带这些数据不代表可以省略兼容性检查或备份；后续版本如涉及迁移，必须按其发布说明核对。

## 签名、通道与回退

- 生产与测试通道保持隔离；不要把 `xshop-preview-` 候选包当作生产更新。
- 1.1.9 保留既有签名 authority、生产频道与单调递增 sequence（11）。不要清空 journal、重置 high-water 或自行换钥绕过校验。
- 程序回退不恢复业务数据库，也不降低 high-water；较旧程序正在运行不代表可以重放已消费的发布序列。
- 失败恢复或持久化状态异常需按已有运维流程调查，不要通过删除状态文件强行再次安装。
